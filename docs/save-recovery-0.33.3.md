# 存档保护与账户恢复

2026年10月21日，修复版本0.33.3。用户反馈微信内小游戏通关记录与金币同时消失。0.33.0至0.33.2之间账户键与AppID均未更换；未直接读取用户手机原始缓存，已在真实Cocos构建中复现根因：集合展开被编译为数组拼接，Set被当作单个元素保存，JSON中出现`[{}]`，成就及后续历史字段因此无效。严格整档校验在下次启动拒绝账户，默认空档又可能覆盖主备存档。

## 已修复的风险

原实现启动时删除历史存档位置，且购买、成就、品阶或改造历史中任一字段校验不通过，就放弃整份账户；随后新局结算可能把默认账户写回主备两份。未知字段与损坏字段应局部处理，不能因此丢失有效金币或通关记录。

- 将所有账户Set转数组改为`Array.from`，不再依赖当前Creator配置对集合展开的编译行为。
- 停止删除旧存档、备份与旧偏好键。旧游戏模式的关卡编号不自动映射到当前十关。
- 稳定使用`ashen-survivors-armory-progress-v1`及其备份，兼容字符串、微信直接存储的对象及双层JSON编码。
- 当前规则下的未知成就、尚未支持的品阶及失效改造历史仅隔离对应字段；有效金币、购买、通关、原有成就和结算去重记录继续保留。
- 可依据现存的明确通关章及胜利最佳记录恢复对应关卡。不会凭最高关卡推断所有前置关卡，也不补造金币或史诗挑战历史。
- 主档钱包损坏时使用有效备份；版本、规则不兼容或存储读取异常且没有有效当前账户时，阻止空白账户自动覆盖原存档。
- 覆盖前保留原始存档快照，保留初始两份和最近十份，共最多十二份。原始副本保存失败时暂停写回，避免同时失去主档、备份与历史。

## 手机上的恢复入口

主菜单左上角进入「存档检查」，查看本机可读的主档、备份及历史副本。每项显示金币、通关关卡、修订及是否经过兼容处理。

点击「预览恢复」只展示所选账户，不扣款、不修改账户。确认后以所选快照的金币、购买和进度为准，不把余额相加；原始当前数据先保留。恢复后重新进入游戏仍应读到相同金币与通关记录。重复确认旧按钮不会重复恢复或发放奖励。

没有可读副本时明确显示结果，不伪造已恢复状态。此功能无法还原已经被微信清除、被旧版本完全覆盖且没有残留副本的数据，也不提供跨设备云存档。修复程序及模拟测试通过不等于已恢复用户手机上的实际数据，需由用户在同一微信环境确认。

## 已确认账户的补回

对于原始数据已被旧版覆盖的情况，提供本地补回码入口：用户复制补回码后，在「存档检查」点击「粘贴补回码」，预览通关范围、金币和默认武器状态，确认后精确替换账户，不叠加余额。代码带校验和防止误复制，不是云端身份认证；同一码用结算记录去重，不能重复补币。写入失败不修改账户，覆盖前仍保留当前原始副本。

此次用户确认补回已通关1～4关、400金币、没有额外解锁武器，使用默认品阶。不补造最佳时间、付费或挑战武器以及跨局探索历史。客户端不能远程修改手机存储，需用户在新版中主动粘贴并确认。

## 0.33.4：真实输入框

微信客户端反馈剪贴板按钮无响应，因此入口改为「存档检查 → 输入补回码」。新增Cocos原生EditBox输入框，可点击后手动输入或长按粘贴，也保留「从剪贴板粘贴」辅助按钮；读取失败留在当前页并提示使用输入框。空码、错误码会显示具体提示并保留已输入文本；「预览补回」不修改账户，最终「确认补回」才保存。输入时暂停菜单快捷键处理，避免字符被导航拦截。
