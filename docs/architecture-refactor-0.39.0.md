# 0.39.0 · 可维护性与扩展性整理

2026-10-22。依据用户“直接优化”的要求，对0.38.3进行保留行为的模块重构。本轮完成本地源码、回归验证与Web/微信构建；未提交远程或上传后台，微信开发后台仍为0.38.3。游戏仍为16关、14个武器系列，关卡机制、数值、奖励、消费和存档字段均保持。

## 已完成的边界

|边界|实现|后续扩展方式|
|---|---|---|
|飞刀行为|`BladeBehavior`独立管理绕身扫掠、追猎/碎刃转向、往返、每轮派生上限和改造切换。通过窄接口使用通用弹体容器、命中与回收，不复制通用伤害代码。|飞刀机制在该模块改动；武器策略可注册`onModification`，通用改造安装流程不再判断具体武器/改造ID。|
|火球/圣水行为|`FireBehavior`维护齐射/蓄力时序、接触爆炸和余烬；`WaterBehavior`维护分散选点、落地、泉眼扩张、波流和召回。|共享弹体/区域池、容量预留、派生同帧保护和同武器重叠伤害去重仍在Armory，避免拆分后各模块自行叠伤。|
|武器图鉴|`WeaponCatalogScreen`负责列表筛选分页、武器简介与四项改造、升级小图标和购买/进阶预览。|菜单控制器保留路由、键盘焦点、提示、确认后扣款与存档提交；绘制函数不直接消费金币。|
|七种扩展武器|`ExtraWeaponBehaviors`以完整类型表登记寒霜、落雷、幽灵、骨矛、地雷、黑洞和圣光；独立模块维护初始化、瞄准/数量特例和逐帧生命周期，使用`ExtraBehaviorPort`访问攻击池与公共命中。|修改骨矛爆裂、幽灵追踪、地雷连线等招式时进入对应模块；通用池容量、冷却、属性快照、更新顺序及黑洞持续/终结伤害分桶仍在ExtraArmory统一处理。|
|选敌优先标记|敌人配置用`priorityTarget`声明普通优先目标，`isPriorityTarget`统一读取；精英自动优先，是否额外优先Boss由调用方明确选择。|新增敌人只需在自身配置注明角色，不继续维护两份按英文名称匹配的长正则。飞刀的Boss中性排名与幽灵追猎/圣光的Boss优先保持，关卡装置优先级仍先执行。|
|成就展示|`AchievementScreen`渲染列表与登记的起手进度页，`AchievementBadges`登记六种徽章绘制，`AchievementProgress`对账户快照作只读文案投影。|菜单保留分类、页码、导航与键盘焦点；ProgressStore保留同名兼容查询，继续负责存储。新增成就展示不再把徽章绘制和进度文案堆入存档或菜单大类。|
|菜单会话导航|`MenuNavigation`管理当前子页面、焦点、按钮动作与返回上下文；方向键仅更新焦点标签，不重建页面和交易闭包。|新增菜单明确父级返回；进阶确认保留消费类型、价格和待确认品阶；起手页、存档确认、恢复及补回码预览使用各自页面类型。输入框焦点移动不丢草稿。|
|存档边界|`ProgressCodec`负责无IO的校验/兼容解码；`ProgressRepository`负责主备与旧位置选择、原始副本归档和受保护写入；`ManualSaveSlots`负责三手动位；`ProgressRepair`负责补回码编码与纯预览。|ProgressStore保留现有查询/交易/结算接口。写入口统一先保留原始副本，账户替换仅在至少一个自动副本成功后确认；版本、键名、修订时机、失败返回和手动位删除墓碑格式不变。|
|关卡战斗规则|`StageCombat`提供旧关规则与可组合护甲规则，策略注册阵营与暴露状态；敌人的基础护甲放在敌人配置。公共世界只调用策略再记实际伤害、统计与死亡。|新增关卡登记自己的战斗策略，不继续往公共伤害入口追加关卡编号判断。伤害乘算、护盾吸收及破绽顺序保持。|
|关卡接入|第5～16关复用`managedStage`适配器，共享导演、敌人/Boss分发、危险类型检查、清理与死亡转发；独特招式仍由各关系统维护。|保留第1～4关特殊调度语义。第9关移动、第12关目标优先、第13关命中回调、第16关初始化/复活由策略接入，移除对应公共世界分支。|
|成就结算|`AchievementRules`在候选账户快照上记录胜利奖励、配装历史和成就；后期起手挑战按关卡注册，重复配方、版本冻结和各关门槛保持。`ProgressData`单独定义原账户结构。|新成就在规则模块注册；存档类继续负责副本、迁移、确认和原子提交，不承载这批成就条件。原`ProgressStore`类型导出保留兼容。|
|关卡HUD|`StageHud`为全部16关登记提示、危险建议、机制进度、招式倒计时和Boss形态标题。|StageId扩展时类型要求补HUD提供者；通用HUD不继续增长关卡提示判断链，金币仍显示在生命旁。|
|选关界面|`StageSelectionScreen`负责布局和绘制，菜单控制器保留预览状态及切换/开始/返回行为。|调整选关画面不需要进入武器图鉴、存档和战斗菜单实现。|

这些变化是职责拆分，不是帧率优化；没有宣称未经测量的性能收益。主菜单的存档/战斗等页面、关卡内部重复的编排算法和美术目录注册仍有后续整理空间，未把本轮描述为整个项目已全面组件化。

## 后续工作约定

1. 新关卡优先通过现有策略扩展；不要为方便重新往公共伤害、HUD或成就提交逻辑添加长关卡判断链。
2. 新武器改造若改变正在运行的攻击，应注册明确切换行为，规定旧攻击是完成、取消还是转换，并说明冷却、派生与去重处理。
3. 本轮快照用于证明重构保留行为，不是永久冻结游戏数值。今后有意调整数值/奖励/提示时，需同步记录理由并更新相应快照；不能隐瞒变化或添加限伤来迎合快照。
4. 持久化字段变更仍需明确迁移、备份和三手动位冷重载验证。此轮只搬移规则和类型，未改账户命名空间或字段格式。

第二轮继续使用同一0.39.0本地开发批次。Armory从第一轮525行降至427行，GameMenus从1093行降至977行；提取代码移入明确职责的模块，文件变短不代表运行性能提升。1056组武器记录及整套653项回归再次通过；两个本地平台包再次构建验证。新增图鉴截图见[武器图鉴](../artifacts/architecture-refactor/browser/weapon-catalog.png)。

第三轮把ExtraArmory从632行整理为187行协调代码，七种武器各自模块为58～136行，外加统一契约和注册表。保留原冻结诊断入口供已有打断回归使用；属性复制、初始化顺序及副本范围使用原施放快照。654项回归中653通过、1项原有跳过，140组攻击过程与1056组数值比对、TypeScript及两个本地平台构建通过。

第四轮把选敌特征收回敌人配置，成就渲染、徽章与只读进度展示独立；不修改成就门槛、奖励、账户字段或提交时机。656项回归中655通过、1项原有跳过，1056组武器记录仍与0.38.3一致，两个本地平台包再次构建通过。界面截图见[成就页面](../artifacts/architecture-refactor/browser/achievement-screen.png)。新成就需分别登记结算条件、进度投影和可选徽章/起手页，并覆盖对应导航与冷重载；展示层不能自行发奖或提交存档。

第五轮完成菜单导航和存档边界整理：菜单焦点移动不再重新渲染页面，修复原进阶确认页方向键会切回购买模式并重置焦点的问题；子页面返回保留父级页码、筛选、焦点，补回码预览取消后回到原草稿。以上为明确的交互修复，不宣称与原错误交互等价。存档原行为则用21组完整IO/字节轨迹及既有故障/迁移/手动位回归证明等价，未引入新账户格式或清理旧存档。全套668项中667通过、1项原有跳过，TypeScript、原50组成就展示和原关卡/结算快照、实际Cocos浏览器及本地Web/微信构建通过。武器运行逻辑未改，第四轮1056组数值记录继续作为本批基线。

运行：`npm test`；`node tools/check-architecture-parity.mjs after`；`node tools/check-current-weapon-balance.mjs artifacts/architecture-refactor/weapon-balance`；`node tools/check-architecture-browser.mjs`。按现有工作流先生成`temp/tests`或构建Web包；不要在其他诊断运行时同时重建共享临时转译目录。
