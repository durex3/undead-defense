# 内容接入与统一验证

本地0.39.0开发流程，2026-10-22。所有命令在项目根目录运行；不推送Git、不上传微信、不提审。

|命令|用途|
|---|---|
|`npm run check:content`|准备离线模块并核对当前关卡、敌人、武器和成就的登记。|
|`npm test`|准备离线模块并运行全部回归；整个任务持有共享目录锁。|
|`npm run verify`|类型检查 → 准备模块 → 内容完整性 → 全部回归 → 架构行为快照。|
|`npm run verify -- --browser`|常规验证后构建Web包，运行独立临时Chrome回归。|
|`npm run verify -- --full`|常规验证 → 武器预算诊断 → Web构建 → 浏览器回归 → 微信本地构建。|
|`npm run verify -- --full --plan`|只打印完整执行顺序，不准备模块、不构建或运行浏览器。|

运行环境：项目依赖已安装，Cocos Creator 3.8.8已生成本地类型配置；浏览器流程使用支持内置WebSocket的Node版本（当前环境为Node 22或更高）。Creator可通过`COCOS_CREATOR`指定路径。现有浏览器脚本默认使用macOS已安装的Google Chrome，不安装浏览器或使用用户Chrome配置。

## 接入检查的范围

`tools/content-audit.mjs`读取当前实际内容列表，不把关卡数永久固定为16或武器数固定为14。当前覆盖16关、106种敌人、14系列、30种可用品阶形态。

- 关卡：配置与提示、地图配色、美术目录、实际战斗策略的敌人归属、Boss及敌人绘制、HUD、通关成就与金币奖励提交。
- 武器：名称/角色/颜色、可用解锁路线、实际可执行的施放策略、四项改造及互斥、数值预算、合法品阶名称/图标/属性，以及实际攻击过程存在绘制提交。
- 成就：唯一ID、分类和介绍/奖励字段、奖励武器存在、通关结算接入；非通关成就同时检查`AchievementRules.ts`中的条件登记引用。引用分析使用TypeScript语法树，不匹配注释，也不维护第二份成就ID清单。
- 故意漏登记的回归：缺关卡、缺武器预算、空图标、敌人归属错误、成就无结算条件引用，必须使检查失败并标出具体内容ID。

这些是接入与受控运行检查。源码中存在成就规则引用不等于条件一定正确；有绘制提交也不等于视觉质量达标。新增机制仍需针对时序、碰撞、派生、奖励与失败场景的行为回归和实际包检查。武器预算诊断不代表真人胜率；检查不要求自动通关。

## 顺序与共享目录

`verify`、`npm test`、内容检查入口、当前武器诊断、`tools/test-build.mjs`和`tools/build.mjs`共用`temp/verification.lock`。锁通过独占创建取得，记录PID和任务；子任务继承同一个会话，避免父任务与自己的构建互相阻塞。独立重复启动直接失败，保留现有临时目录与检查报告。正常结束或抛出异常均释放锁；取消受控子任务时先等待其退出。

浏览器流程为本次任务启动随机端口的127.0.0.1静态服务器，结束时关闭；无需额外运行8128服务器。直接使用旧诊断脚本仍可能只锁住转译步骤，没有覆盖后续读取；不要与统一入口并行运行旧诊断。

强制终止后若留下锁，先确认锁内PID及其Creator子进程均已结束，再移除单个`temp/verification.lock`。不要通过清空`temp/tests`或`build`来解锁。

## 结果与基线

- `artifacts/verification/content.json`：具体内容缺项。
- `artifacts/verification/latest.json`：最近一次取得锁的统一验证结果，含模式、步骤、耗时与失败步骤。
- `artifacts/verification/standard.json`、`browser.json`、`full.json`：各模式的最近结果，运行对应模式后生成。
- `artifacts/architecture-refactor/browser/browser-report.json`：实际包检查与截图。
- `temp/build-logs/`：Creator构建原始输出。

任一步失败即停止后续步骤并返回非零退出码。行为快照沿用0.39.0重构前记录；今后有意改变数值、奖励、提示或存档语义时，说明理由并同步更新对应快照，不能只改快照来掩盖缺陷。完整验证生成微信本地包后结束，发布仍是独立任务。
